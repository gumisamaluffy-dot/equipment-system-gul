# Метод и стратегия разработки

## 1. Общая информация

Разрабатываемый проект — система учёта оборудования колледжа и управления заявками на ремонт.

Основная задача проекта — упростить работу с оборудованием, сделать его учёт более удобным и ускорить обработку заявок на ремонт. Для этого необходимо создать систему, в которой можно хранить информацию об оборудовании, просматривать его состояние, находить нужные устройства и отслеживать ремонтные заявки.

## 2. Выбранный метод разработки

Для разработки проекта выбран поэтапный метод. Он предполагает разделение всей работы на отдельные этапы. Каждый этап выполняется последовательно, а его результат проверяется перед переходом к следующему.

Такой подход позволяет:
- правильно организовать работу;
- не пропускать важные задачи;
- своевременно обнаруживать ошибки;
- контролировать выполнение проекта;
- постепенно улучшать систему.

## 3. Основные этапы разработки

### Этап 1. Анализ требований

На первом этапе изучается проблема учёта оборудования колледжа. Определяются основные пользователи системы, их задачи и необходимые функции.

Результат: техническое задание с описанием требований к системе.

### Этап 2. Проектирование системы

На этом этапе разрабатывается структура будущей системы. Определяются основные компоненты, связи между ними и способы взаимодействия пользователей с системой.

Также создаются диаграммы, которые показывают работу системы и последовательность выполнения основных действий.

Результат: схемы и описание структуры системы.

### Этап 3. Проектирование базы данных

Определяется, какая информация будет храниться в системе. Создаются таблицы для оборудования, пользователей и заявок на ремонт. Определяются связи между таблицами.

Результат: структура базы данных.

### Этап 4. Разработка интерфейса

Создаётся внешний вид системы. Предусматриваются страницы для просмотра оборудования, добавления новых устройств, создания заявок и просмотра информации о ремонте.

Интерфейс должен быть понятным и удобным для пользователей.

Результат: макеты и основные элементы интерфейса.

### Этап 5. Тестирование

После разработки отдельных частей системы проводится проверка их работы. Проверяется правильность добавления оборудования, поиска устройств, создания заявок и изменения их статусов.

При обнаружении ошибок они исправляются.

Результат: проверенная и исправленная система.

### Этап 6. Подготовка итогового проекта

На последнем этапе все материалы собираются вместе. Проверяется документация, диаграммы и результаты работы. Подготавливаются итоговый PDF-файл и презентация проекта.

Результат: готовый проект с документацией.

## 4. Стратегия разработки

Разработка будет выполняться постепенно, начиная с основных функций и переходя к более сложным.

Сначала необходимо определить требования и спроектировать систему. Затем подготовить структуру базы данных и интерфейс. После этого можно переходить к реализации основных функций и их проверке.

Особое внимание будет уделяться:
- удобству использования системы;
- правильности хранения информации;
- быстрому поиску оборудования;
- надёжной обработке заявок;
- понятному отображению статусов ремонта;
- своевременному обнаружению ошибок.

## 5. Используемые инструменты и технологии

Для выполнения проекта планируется использовать следующие инструменты:

| Инструмент | Назначение |
|---|---|
| GitHub | Хранение файлов и управление проектом |
| Draw.io | Создание диаграмм и схем |
| SQL | Проектирование и работа с базой данных |
| HTML | Создание структуры веб-страниц |
| CSS | Оформление интерфейса |
| Markdown | Оформление проектной документации |

## 6. Распределение времени

Общая продолжительность проекта составляет 144 часа.

Время распределяется между анализом требований, проектированием, разработкой, тестированием и подготовкой итоговых материалов.

Каждый этап выполняется в соответствии с планом проекта. При необходимости время может корректироваться в зависимости от сложности задач.

## 7. Ожидаемый результат

В результате разработки должна быть создана система, которая позволит:

- вести учёт оборудования колледжа;
- хранить информацию об устройствах;
- быстро находить необходимое оборудование;
- создавать и обрабатывать заявки на ремонт;
- отслеживать состояние заявок;
- получать информацию о состоянии оборудования.

Разработка поэтапным методом позволит организовать работу над проектом, контролировать выполнение задач и получить понятную и удобную систему учёта оборудования.
